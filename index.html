How it works

From a config file to an alert in three steps

StoragebackmonPrometheusAlertmanager
  • 1. Describe
  • 2. Scan
  • 3. Alert

Tell backmon which disks to watch and what a healthy backup group looks like.

config.yaml
environments:
  aws-test-environment:
    disks:
      include:
        - s3-photos
    region: eu-central-1

On every interval it inspects your storages and exposes the result for Prometheus.

GET /metrics
backmon_backup_file_count{disk="mysql-dumps"} 7
backmon_backup_file_count_max{disk="mysql-dumps"} 7
backmon_backup_file_count{disk="s3-photos"} 0
backmon_backup_file_count_max{disk="s3-photos"} 4

A Prometheus rule on those metrics notifies your team before you ever need the backup.

alert rule
- alert: BackupMissing
  expr: backmon_backup_file_count
    < backmon_backup_file_count_max
  for: 15m
FIRING  disk="s3-photos"

FAQ

Questions, answered

More in the docs →
What does backmon monitor?

The presence, size and timestamps of recurring backup files in a filesystem or an S3-compatible object storage. It does not create backups.

Does it work with MinIO?

Yes. Any S3-compatible storage works, including AWS S3 and MinIO.

How do I get alerts?

backmon exports Prometheus metrics. Use Alertmanager rules on those metrics to notify your team.
